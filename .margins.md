# Margins rules — sickrabbit-theme

A forked-and-restyled Shopify Dawn theme. `main` is connected to the live store and deploys on merge, so review bar is high.

## Stack
- Shopify Dawn theme (Online Store 2.0)
- Liquid templating + JSON templates under `templates/*.json`
- Styling: CSS custom properties layered on Dawn's token system (`assets/base.css`, brand tokens)
- Vanilla JS only — no framework, no build step
- Dawn tracked as `upstream` remote; changes must stay merge-friendly

## Always flag
- Hardcoded colours, font sizes, spacing, or radii in section/snippet CSS — must use Dawn CSS custom properties or Sick Rabbit tokens. Raw hex/px/rem literals for these are a finding.
- Brand colours bypassing Dawn's colour-scheme system instead of going through `color-scheme` settings.
- Renaming or deleting Dawn's existing files (anything under `assets/`, `sections/`, `snippets/`, `templates/`, `layout/`, `locales/` that ships with Dawn) — changes must be additive to keep `git merge upstream/main` tractable.
- A `templates/*.json` file replaced by a `.liquid` template, or a section missing its `{% schema %}` block (with `presets`/`settings`/`blocks`) — breaks merchant editability in the theme editor.
- Business logic reimplemented in Liquid/JS that Shopify already provides — money formatting, translations (`t:` / `{{ ... | money }}`), cart, variants. Use the filters and objects, not shims.
- Client-side JS added where an HTML-first / Liquid solution exists. Dawn is HTML-first, JS-as-last-resort.
- Merchant-controllable values hardcoded instead of exposed via section schema or `config/settings_schema.json`.
- A block of Liquid duplicated across 2+ sections/snippets that should be extracted to a shared snippet.
- Naming drift: snippets/sections/CSS files not kebab-case; Liquid variables not snake_case; locale keys not dot-separated snake_case.

## Allow without flagging
- Edits to `config/settings_data.json` and `templates/*.json` — these are auto-committed by the Shopify admin/GitHub bot when merchants edit in the theme editor. Don't flag them as code-quality issues.
- Additive CSS overrides via custom properties (the intended restyle mechanism).
- TODO comments referencing a phase or roadmap item.

## Ignore entirely
- `LICENSE.md`, `.github/`
- Minified/vendored assets shipped by Dawn that the PR doesn't author

## Architectural notes
- Decisions are logged in `docs/decisions.md` — a change that contradicts a logged decision is worth flagging.
- Component conventions: reusable markup → `snippets/`, reusable content blocks → `sections/` (with schema), page composition → `templates/*.json`. Primitive markup living directly in a template instead of a snippet is a smell.
- New design-system values must be added to `docs/design/system.md` + `assets/base.css` before use — a one-off value with no token backing is a finding.
